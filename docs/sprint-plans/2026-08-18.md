# Progress, Blockers, and Plan — August 18, 2026

Covers everything since the last check-in (`docs/STATUS_AND_SCOPE.md`,
last written Aug 17). Today is 5 weeks from Demo Day (September 23, 2026).

## Progress

**X (Twitter) manual-click publish — built and live-verified.**
Full OAuth 2.0 + PKCE connect flow, encrypted token storage
(`social_connections`/`social_posts`/`oauth_pkce_states` tables), and a
"Connect X" / "Post to X" button on the review page. A human clicks
Connect once, then Post per item — nothing fires automatically, per the
Aug 8 manual-click scope decision. 58/58 backend tests passing.

**Real WVF X post templates added.** 6 real, previously-published
`@WomensVFund` posts transcribed into a Fixed-template picker, same
pattern as the Instagram templates from Aug 17. Entries with a truncated
source (a cut-off URL in the original screenshot) now carry an explicit
`truncated` flag and warning in the UI, rather than silently presenting
incomplete copy as finished — this fix was also applied retroactively to
2 Instagram entries that had the same issue.

**Event form reorganized into two labeled sections.** "Social Media
Copy" (Instagram/LinkedIn/Facebook/X/TikTok) and "Email Copy" (Keymakers)
now each have their own heading and a dedicated "AI Generate" button —
Social's opens a platform picker, Email's jumps straight to generation.
Platform tiles keep their existing AI Copy vs. Fixed template choice
unchanged.

**Live generation fixed end-to-end.** After Anthropic billing was funded
with a $5 balance, three real, separate bugs were found and fixed by
testing directly against the live Railway backend rather than assuming
success:
1. Every Claude call used a stale, no-longer-valid model ID
   (`claude-sonnet-4-20250514`) — replaced with `claude-sonnet-5` across
   all 11 generation call sites.
2. None of those 11 calls forced tool use (`tool_choice`), so Claude
   could technically skip or partially fill the structured response —
   surfaced as a real failure (`HashtagsOutput` missing its required
   `rationale` field). Fixed on all 11 calls, not just the one that failed.
3. The content-calendar prompt's wording ("Label each entry clearly")
   collided with the schema's actual field name (`day_label`), causing
   Claude to invent a `label` key instead. Reworded to name the field
   explicitly.

**Verified via a real POST to the live endpoint** (not just local
testing): full 200 response, 3 social post variants, 3 hashtag sets,
newsletter, flyer, and a 9-entry calendar with correctly-named fields
throughout. Generation is confirmed working on the deployed site as of
today.

**Fixed a second, unrelated pre-existing bug found along the way:**
`alembic upgrade head` had been broken on SQLite since Aug 4 (a
migration used raw Postgres-only DDL) — nothing caught it because the
test suite builds its schema a different way. Fixed with dialect-aware
migration logic; verified with a real upgrade/downgrade round-trip.
Already-applied on the live Postgres DB, so this was a local-dev-only
fix with zero effect on production.

## Blockers

**Meta App Review — still not started.** This was already the
longest-lead-time item as of Aug 17 (6–8 week review window, ~5 weeks
now left to Demo Day) and remains untouched. This is the single most
time-sensitive open item on the whole list — needs to start immediately
regardless of what else is in flight.

**ESP (email service provider) selection — still unconfirmed.** Blocks
starting the DNS setup and the 4–6 week domain warm-up ramp. Every week
without a decision here is a week lost against a shrinking runway.

**X Developer Portal / Railway setup — needs a person to complete, not
code.** The connect flow is built and tested, but actually usable only
once: the X app is registered with the correct type ("Web App,
Automated App or Bot" — not "Native App," which won't issue a Client
Secret at all), the callback URL matches `BACKEND_URL` exactly, and
`X_CLIENT_ID`/`X_CLIENT_SECRET`/`TOKEN_ENCRYPTION_KEY`/`BACKEND_URL`/
`FRONTEND_URL` are all set on Railway. (Status as of the last check —
confirm current state before assuming this is still open.)

**Newsletter-blocks frontend UI still not built.** The backend
(schemas, generators, endpoints for all 6 modular sections) has existed
since Aug 4; there's still no frontend flow to generate or review
individual blocks. Largest built-but-unexposed gap in the app.

**Two open client-decision items, unchanged:** "Key Makers" definition
(Nancy's 10 real testimonial clients vs. Felix's 4 GHL personas — still
two different concepts) and full-newsletter-vs-individual-blocks
generation model. Both block downstream work and have been open for over
a week.
